# M1 — Revalidate the ChatGPT Loop

## Goal

Verify and repair the existing extension against the current ChatGPT web UI before building new server complexity.

## Implementation note — 2026-08-22

The restart branch now contains the first revalidation hardening pass: composer/send selectors are scoped and ranked more conservatively, the overlay can export DOM/selector diagnostics, and tool calls keep an in-memory correlated state trace. These changes are implemented but runtime-sensitive boxes remain unchecked until verified in a real current ChatGPT session.

The first Windows acceptance run verified a clean `npm ci`, all current tests, and a successful patched `npm run build` for both extension and broker. The unpacked extension was then loaded in current Edge and the **Tool Shim · restart** overlay rendered successfully on `chatgpt.com`.

The first live conversation traffic verified that the current assistant-message selector detects real model output and that `hello`, `clock`, and `browser.tabs.list` execute end-to-end. With Auto Submit disabled, each result was inserted into the ChatGPT composer and could be manually submitted, verifying insert-only delivery. The large `browser.tabs.list` response also demonstrated that ordinary inline delivery remains functional for the current result size.

A later `hello` call was initially misclassified as a successful Auto Submit test because the result appeared in the conversation; the user clarified that they had manually pressed Send. Auto Submit therefore remained unverified. The first verified Auto Submit retry exposed a concrete failure instead: the shim found an enabled send control and invoked `.click()`, but ChatGPT did not consume the composer within five seconds. The success result and the compact `RESULT_DELIVERY_ERROR` remained together in the composer and were later manually submitted, proving the programmatic click had not produced a send transaction.

A subsequent observation showed that the shim also opened ChatGPT's **plus/add files/apps/modes** menu during an Auto Submit attempt. Inspection found the submit selector still accepted generic `button[type="submit"]` controls and rewarded `type="submit"` during fallback ranking. That is no longer allowed: candidate controls must now carry positive Send semantics (`send-button`, `Send prompt`, `Send message`, or equivalent), while add/files/apps/tools/modes/menu/plus/attachment controls are explicitly rejected. If no positively identified Send control exists, the shim fails safely rather than clicking another composer control.

The submit implementation uses a verified fallback ladder rather than trusting `.click()`: first the composer form's native `requestSubmit()`, then synthetic mouse activation on the selected send control, then an Enter-key fallback. Each attempt is accepted only after a real page-side success signal is observed (composer cleared or a new `[data-message-author-role="user"]` node appears). If all methods fail, the error records the selected button's type/test-id/aria-label/form association plus the outcome of every attempted activation method. Auto Submit remains unchecked until this revised path succeeds in the live page.

That same testing exposed that identical autogenerated calls reused a content-derived call ID across page reloads (`call_52f675cf`). The parser was subsequently changed so autogenerated IDs combine a random per-content-script session nonce with a stable content hash: rescans in one page lifetime keep the same ID/fingerprint for dedupe, while the same call after a reload gets a distinct execution ID. The next live call returned `call_79e1d68779aac52c_52f675cf`, verifying the session-unique execution-ID behavior. Explicit model-provided IDs remain preserved.

The restart HUD is now draggable by its title bar and persists its last viewport-constrained position across ChatGPT reloads so it can be moved away from page controls/content during testing.

The canonical local iteration command is now the full extension+broker refresh sequence:

```powershell
git pull --ff-only; npm test; npm run build; npm run server:start
```

This keeps browser and broker artifacts synchronized during the restart instead of optimizing for partial rebuilds.
